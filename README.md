# AI-auto-pages 发电站

一个纯静态的支持页：访客选项目、看提示、点按钮打开链接、看常见问题；维护者用编辑页改数据，不用改代码，也没有自己的服务器。

- 主页：https://ai-auto-pages.github.io/
- 编辑页：https://ai-auto-pages.github.io/edit.html（不从主页链接，搜索引擎不收录）
- 仓库：`AI-auto-pages/ai-auto-pages.github.io`，分支 `main`，用 GitHub Pages 发布。

## 访客怎么用

主页只有三张卡片：说明、选择项目、常见问题，底部有一行声明。

- 下拉框选项目，详情区显示该项目的提示内容，按钮变成“去发电”，点开新窗口打开项目链接；没选时按钮是“请先选择”且禁用。
- 常见问题按数据里的顺序渲染，每个问题可折叠，回答按 HTML 渲染；如果常见问题列表为空，整节隐藏。
- PC 端主页一屏显示完，不滚动；移动端按正常流式布局滚动。

## 维护者怎么改：编辑页

打开 `edit.html`，页面先加载当前数据并显示成表单，改完点底部保存才提交。

- 基本设置：只改页面标题。
- 项目：每张卡片依次是名称、链接、价格、提示区，提示区下方有实时预览，样式和主页详情区一致。
  - 左上是序号输入框 + 确定按钮：序号从 1 开始，最上面就是 1，输数字点确定（或按 Enter）可直接排到该位置，超出范围会报错。
  - 右上是上移、下移、删除：删除前会确认。移动、新增都会先保留当前页面顺序。
- 新增项目、下载 JSON 备份在项目列表下方靠右；下载只下载当前表单内容，不提交。
- 常见问题在项目列表下方单独一节，每张卡片是问题、回答（可填 HTML）、预览，右上同样有上移、下移、删除，新增常见问题按钮在该节下方靠右。
- JSON 预览卡片里是“查看当前 JSON（只读预览）”，只看不改。

### 保存

底部固定栏只有两样东西：令牌输入框（提示语只有“令牌”）和“保存并提交到仓库”按钮。

- 令牌不写进代码、不持久化，只在本次页面里使用，只发给 `api.github.com`。
- 保存前先拉仓库最新版和 SHA：如果和你加载时不一样，会弹确认，确定是用你的内容覆盖，取消是重载最新版再编辑。
- 校验：项目名不能为空，常见问题的问题不能为空；项目列表为空会二次确认。
- 成功后等 Pages 重新部署几分钟，主页刷新才会变。不要把 Pages 延迟当成保存失败。

### 直接改仓库也行

只改 `data/site.json`，提交后等 Pages 部署即可，格式见下一节。

## 数据：`data/site.json`

这是唯一数据源。页面运行时直接 `fetch` 它（带时间戳防缓存），不是预渲染，也不做后台定时更新。改数据不用改代码。

```json
{
  "title": "页面标题",
  "products": [
    { "name": "项目名", "url": "项目链接", "price": 1, "tips": "提示区 HTML" }
  ],
  "faqs": [
    { "问题": "蓝奏云打不开？", "回答": "回答 HTML" }
  ]
}
```

- 顺序就是数组顺序：`products` 和 `faqs` 在数组里的先后，就是页面上显示的先后。
- `tips` 和 `回答` 是 HTML，直接渲染，只填自己信任的内容。
- 读取时常见问题也兼容 `question` / `answer`，但编辑页保存时一律写中文键 `问题` / `回答`。
- 价格空着保存时按 1 处理。
- 不要恢复旧字段：`api_url`、`plan_id`、`gcode`、`cipher_key` 和支付链接生成已经删掉，主页按钮就是直接打开 `url`。旧文件 `admin.html`、`data/admin.json`、`data/projects.json`、`style.css` 也已经删掉，不要恢复。

## 主题：浅色 / 深色 / 跟随系统

右上角固定有一组三个小按钮，分别用 ☀（浅色）、🌙（深色）、🌓（跟随系统）表示，当前选中的是青色底。点一下就切换，存在浏览器里，主页和编辑页共用，刷新还在。

- 浅色是柔和暖纸色：页面底不是纯白，卡片是暖米白，字是深棕灰不是纯黑，对比够看清又不刺眼。
- 深色是护眼暖深色：底不是纯黑，字不是纯白，颜色都降了饱和度，不发亮。深色不是靠浏览器系统媒体查询硬改几个盒子（以前就是这么出 bug 的：盒子变深、字还是深色，根本看不清），而是 JS 按选择设置 `data-theme`，跟随系统时 JS 监听系统变化再改 `data-theme`，手动选的浅色/深色永远优先于系统。
- 改样式时注意：浅色和深色都要在 `bulma-theme.css` 的 `:root` / `[data-theme="dark"]` 里成对写，不要只写一边的硬编码颜色，不要再加 `prefers-color-scheme` 的媒体块。

## 开发设计思路

- **静态优先**：无服务器、无构建、无预渲染。数据一个 JSON 文件管到底，编辑页只是这个 JSON 的表单，逻辑都在两个 HTML 的内联脚本里。
- **Bulma 为主，自定义为辅**：卡片、按钮、下拉、表单、按钮组尽量用 Bulma 原生组件，字体用 Bulma 默认字体。自定义只放在 `bulma-theme.css` 里：主题变量、保留的卡头效果、几个不得不写的特例。不要在元素上写内联样式，不要再加第二个自定义样式文件。
- **卡头是固定视觉**：渐变背景、标题前 5×20 青绿到金色的装饰条（`card-header::before`）、标题后渐变细线（`card-header::after`）。改主题时别动这三样，它们的颜色写死为 `#0f766e` / `#d97706`，不随主题变量漂移。
- **宽度流式，不写死像素**：不用 Bulma 的 `.container`（太宽），用 `.site-container` / `.edit-container`：`width: 100%` + rem 上限 + `margin-inline: auto`。桌面居中且宽度受限，移动端占满屏幕宽度。
- **addons 的规矩**：共用边框、同一高度、接缝颜色由常态决定。悬浮只变背景，不变边框：边框宽度（属性和 Bulma 变量都锁 1px）、边框颜色、`z-index` 都锁死，无阴影、无抬升。否则接缝会翻色、看起来像位移。序号控件同理：宽 80px，输入框右边框就是分隔线。
- **缓存与部署**：主题文件引用带 `?v=日期-序号`（如 `?v=20261026-18`），改样式后要同步改这个号，不然浏览器可能还用旧样式；数据请求带时间戳。Pages 部署有延迟，改完先看提交记录和原始文件，再等几分钟看主页。

## 常见坑（以前踩过的）

- 排序“没生效”：多半是新增后重渲染丢了当前顺序，或者 Pages 还没部署完，不是保存失败。
- 样式改了没效果：先核对 HTML 里的类名和 CSS 里的选择器是不是同一个（以前出过 HTML 是 `orderInput`、CSS 写 `.order-input`，规则根本没命中）。
- 悬浮边框变：Bulma 的描边按钮悬浮会把边框变到 2px，addons 悬浮还会把按钮抬高导致接缝翻色。现在的做法是把宽度、颜色、`z-index` 都锁死，悬浮只变背景。
